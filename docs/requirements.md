## 2. 产品概述

### 2.1 产品定位

本产品是一款面向个人开发者和小型开发团队的 Windows Git 库管理工具，用于在一个桌面应用内统一管理 GitHub、Gitee、GitLab 远程仓库和本地 Git 仓库，并提供项目分析、迭代查看、开发任务执行和备份恢复能力。

产品重点解决以下问题：

- 用户需要在多个代码托管平台之间切换，账号和仓库入口分散。
- 本地仓库数量较多，难以快速定位、收藏和了解项目状态。
- 常用 Git 操作依赖命令行，状态、冲突和错误信息不够集中。
- 项目的构建、运行、打包命令缺乏统一入口。
- 项目摘要、目录结构、提交迭代和备份信息缺乏可视化管理。

### 2.2 产品目标

首版目标：

1. 提供稳定、可追踪的远程账号和令牌管理。
2. 支持 GitHub、Gitee、GitLab 远程仓库和本地仓库的统一管理。
3. 覆盖日常 Git 仓库操作：创建、删除、修改、克隆、导入、拉取、推送、同步、移动和备份。
4. 为项目提供收藏、摘要、AI 摘要、结构分析和迭代时间线。
5. 提供构建、运行、打包任务的一键执行和实时日志。
6. 在 Windows 环境下保证凭据安全、文件操作可恢复、错误信息可理解。

### 2.3 非目标

首版不包含以下能力：

- 完整代码编辑器或 IDE 功能。
- 在线代码编辑、在线 Pull/Merge Request 审查和多人实时协作。
- 自建 Git 服务、CI/CD 服务或云端备份服务。
- 移动端、macOS 和 Linux 客户端。
- AI 自动修改代码、自动提交代码或自动推送代码。
- 独立的敏捷项目管理系统，如需求、工单、燃尽图和团队排期。
- 自动生成或托管用户的 SSH 私钥。

## 3. 用户与使用场景

### 3.1 目标用户

| 用户 | 特征 | 核心诉求 |
| --- | --- | --- |
| 个人开发者 | 同时使用多个平台，维护多个本地项目 | 快速查看、同步、运行和备份项目 |
| 学习者 | Git 命令经验有限 | 通过可视化操作降低 Git 使用门槛 |
| 小型团队成员 | 需要频繁切换仓库和分支 | 统一管理账号、项目和日常任务 |
| 项目维护者 | 维护多个版本和发布分支 | 查看提交迭代、标签和项目演进 |

### 3.2 典型场景

1. 用户添加 GitHub、Gitee 或 GitLab 账号，测试连接并查看远程仓库。
2. 用户从远程仓库列表克隆项目到默认目录。
3. 用户扫描一个已有项目目录，将其中的多个 Git 仓库导入应用。
4. 用户查看项目当前分支、未提交修改、远程领先/落后状态和最近提交。
5. 用户执行拉取、推送或同步，遇到冲突后查看冲突原因并转到本地处理。
6. 用户为项目配置构建、运行、打包命令，一键执行并查看实时输出。
7. 用户查看项目目录结构、语言统计、依赖文件、入口文件和 AI 生成摘要。
8. 用户按照提交、分支、标签和版本时间线查看项目迭代过程。
9. 用户将项目完整备份为 ZIP，并在新目录恢复为可用 Git 仓库。
10. 用户移动本地项目位置，应用完成复制、校验、更新记录和源目录处理。

## 4. 产品范围与版本规划

### 4.1 首版范围

首版必须包含：

- GitHub、Gitee、GitLab 账号管理。
- OAuth 和 Personal Access Token 两种远程认证方式，具体平台能力以平台 API 支持为准。
- Windows Credential Manager 凭据安全存储。
- 远程仓库查询、搜索、创建、修改、删除、克隆和刷新。
- 本地仓库导入、初始化、克隆、登记、移动、备份和恢复。
- Git 状态、提交、拉取、推送、获取、同步、分支切换和冲突提示。
- 项目收藏、标签、摘要、备注和最近操作。
- 目录树、语言统计、文件数量、依赖文件和入口文件分析。
- AI 项目摘要生成、重新生成、编辑、保存和删除。
- 提交时间线、分支、标签和版本信息查看。
- 构建、运行、打包任务的配置、执行、停止和日志查看。
- 本地操作记录、失败原因和基础日志导出。
- 应用设置、Git 环境检测、默认目录和日志策略。

### 4.2 后续版本候选

- GitLab 之外的更多托管平台。
- OAuth 授权范围可视化和账号授权续期提醒。
- SSH 密钥生成、托管和测试。
- Pull/Merge Request 查看、创建和审查。
- Issue、Release 和代码评审状态聚合。
- 可选的云端项目索引和跨设备同步。
- AI 代码问答、变更总结、提交信息建议和风险分析。
- 项目模板、团队共享任务配置和插件扩展机制。

## 5. 信息架构

应用采用桌面端主窗口，建议使用左侧导航、顶部上下文栏和内容区布局。

### 5.1 一级导航

1. 总览
2. 我的项目
3. 远程仓库
4. 账号与令牌
5. 任务中心
6. 备份中心
7. 操作记录
8. 设置

### 5.2 关键页面

#### 总览

展示最近访问项目、收藏项目、需要同步的项目、任务执行状态、最近失败操作和备份状态。

#### 我的项目

支持按收藏、标签、平台、项目状态、本地路径和最近访问时间筛选。每个项目显示名称、平台、当前分支、工作区状态、同步状态、摘要和最近提交。

#### 项目详情

项目详情页是首版核心页面，至少包含以下视图：

- 概览：项目摘要、平台、路径、远程地址、当前分支和工作区状态。
- Git 操作：提交、拉取、推送、获取、同步、分支切换和远程管理。
- 文件结构：目录树、文件统计和重点文件识别。
- 迭代记录：提交时间线、分支、标签和版本对比入口。
- 任务：构建、运行、打包任务和执行历史。
- 备份：备份、恢复、备份记录和校验结果。
- 设置：收藏、标签、摘要、任务配置和项目路径。

#### 远程仓库

按平台和账号聚合远程仓库，支持搜索、创建、修改、删除、克隆和刷新。平台 API 不支持的字段必须在界面中明确标记，而不是静默失败。

#### 账号与令牌

集中展示账号平台、用户名、认证方式、连接状态、权限检查结果、令牌有效期和最后使用时间。令牌正文不可回显。

#### 任务中心

集中展示运行中、已完成和失败的构建、运行、打包任务，支持查看日志、停止任务和重新执行。

## 6. 详细功能需求

需求优先级定义：

- P0：首版必须交付。
- P1：首版建议交付，若影响稳定性可顺延。
- P2：后续版本候选。

| 编号 | 优先级 | 需求 |

| FR-001 | P0 | 首次启动检测操作系统版本、系统架构、Git CLI 是否安装及版本。 |
| FR-002 | P0 | 支持用户选择或修改 Git 可执行文件路径。 |
| FR-003 | P0 | 检测默认项目目录、备份目录和应用数据目录是否可读写。 |
| FR-004 | P0 | Git 不可用时给出安装提示和配置入口，不允许静默进入不可用状态。 |
| FR-005 | P0 | 应用重启后恢复项目记录、账号元数据、任务配置、用户设置和操作记录。 |
| FR-006 | P1 | 支持系统托盘运行、关闭确认和任务运行期间防止误退出。 |

### 6.2 远程账号与认证

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-101 | P0 | 支持添加 GitHub、Gitee、GitLab 账号。 |
| FR-102 | P0 | 支持 OAuth 授权登录；平台或环境不支持时提供 Personal Access Token 方式。 |
| FR-103 | P0 | 支持录入、替换、验证和删除 Personal Access Token。 |
| FR-104 | P0 | 令牌正文只写入 Windows Credential Manager，SQLite 不保存明文令牌。 |
| FR-105 | P0 | 账号添加和令牌变更后执行连接测试，并展示可用权限和失败原因。 |
| FR-106 | P0 | 应用重启后保留账号登录状态，不要求用户重复输入有效凭据。 |
| FR-107 | P0 | 账号列表展示平台、用户名、认证方式、状态、最后检查时间和令牌过期提醒。 |
| FR-108 | P0 | 账号删除前要求确认；删除账号不自动删除本地仓库或远程仓库。 |
| FR-109 | P0 | Git 操作不得将令牌拼接进远程 URL，也不得出现在界面、异常和日志中。 |
| FR-110 | P1 | 支持同一平台添加多个账号，并在项目级别选择默认账号。 |
| FR-111 | P1 | OAuth 回调失败、取消授权和授权范围不足时提供可操作的恢复提示。 |

认证说明：

- OAuth 的授权流程、回调方式和权限范围按各平台公开 API 和 OAuth 规范实现。
- Personal Access Token 的创建仍由用户在平台侧完成，应用只负责安全录入、校验和使用。
- SSH 远程地址首版允许调用用户现有的系统 SSH 配置，但不负责生成或托管 SSH 私钥。

| 编号 | 优先级 | 需求 |
| --- | --- | --- |
| FR-301 | P0 | 支持通过目录导入已有 Git 仓库。 |
| FR-302 | P0 | 支持扫描指定目录并发现其中的 Git 仓库，导入前展示待导入列表。 |
| FR-303 | P0 | 支持在指定目录初始化新 Git 仓库。 |
| FR-304 | P0 | 支持从远程仓库克隆并登记本地仓库。 |

| FR-306 | P0 | 支持仅从应用中移除仓库记录，不删除磁盘文件。 |
| FR-307 | P0 | 支持移动本地仓库。移动流程必须包含复制、完整性校验、更新记录和源目录处理。 |

| FR-309 | P0 | 支持为本地仓库重新绑定或修改远程地址。 |
| FR-310 | P1 | 支持对本地仓库路径进行周期性存在性检查并标记失效路径。 |

删除语义：

- “移除记录”只操作应用数据库，不触碰本地文件。
- “删除本地文件”必须单独执行并二次确认，可选是否同时移除应用记录。
- 删除远程仓库与删除本地目录必须使用不同的操作入口和风险提示。

| FR-413 | P1 | 支持配置 pull 使用 merge 或 rebase；默认值为 merge。 |
| FR-414 | P1 | 支持暂存区、工作区和提交范围的分组操作。 |
| FR-415 | P1 | 支持标签创建、查看、删除和推送。 |

约束：

- Git 操作优先通过系统 Git CLI 执行，命令参数必须使用结构化参数传递，避免拼接注入。
- 任何可能丢失用户修改的操作都必须在执行前检查并明确提示。
- 应用不自动执行强制推送、硬重置、清理未跟踪文件等高风险操作。

隐私要求：

- AI 功能默认关闭远程发送，必须由用户主动配置并触发。
- 发送前显示文件和数据范围；默认排除源代码、密钥文件、环境变量文件和大文件。
- 应用应提供敏感文件名和敏感内容模式的基础过滤，并允许用户配置额外排除规则。

## 7. 核心业务流程

### 7.1 首次启动

1. 应用启动并检查 Windows 版本和系统架构。
2. 检查 Git CLI 是否可用，获取版本和路径。
3. 检查应用数据目录、默认项目目录和默认备份目录。
4. 若存在问题，展示具体原因和修复入口。
5. 用户可跳过账号添加，直接导入本地仓库。

### 7.2 添加远程账号

1. 用户选择 GitHub、Gitee 或 GitLab。
2. 用户选择 OAuth 或 Personal Access Token。
3. OAuth 流程打开系统浏览器完成授权，并通过安全回调返回应用。
4. Token 流程由用户输入令牌，应用立即写入 Windows Credential Manager。
5. 应用调用平台 API 读取当前用户信息和权限。
6. 测试成功后保存账号元数据；失败时不保存无效凭据，或允许用户重试。

### 7.3 克隆远程项目

1. 用户在远程仓库页面选择仓库并点击克隆。
2. 应用建议默认目标目录，用户可以修改。
3. 应用检查目标目录是否为空、磁盘空间是否足够、路径是否合法。
4. 用户确认后执行克隆。
5. 应用扫描仓库信息，写入本地仓库记录和项目元数据。
6. 克隆失败时保留错误日志，并根据实际情况清理不完整目录或提示用户处理。

### 7.4 同步项目

1. 应用读取当前分支、工作区状态和远程跟踪关系。
2. 若有未提交修改，显示风险提示。
3. 用户确认后执行 fetch 和 pull。
4. 应用解析成功、无变化、冲突、权限失败和网络失败等结果。
5. 成功后刷新项目状态、提交时间线和远程领先/落后状态。
6. 冲突时停止自动后续操作，保留冲突现场并列出冲突文件。

### 7.5 移动本地项目

1. 用户选择新的目标目录。
2. 应用检查目标路径与源路径不是同一路径，且目标不存在或为空。
3. 应用复制全部项目文件，包含 `.git`。
4. 应用比较文件数量、大小和校验结果。
5. 校验成功后更新 SQLite 中的项目路径。
6. 用户确认后删除源目录；默认不自动删除源目录，除非用户明确选择“移动并删除源目录”。
7. 任一步骤失败时保留源目录并标记目标为未登记临时目录。

### 7.6 AI 摘要生成

1. 用户在项目详情页主动点击生成摘要。
2. 应用列出项目名称、README、目录结构、依赖清单和提交摘要等待发送信息。
3. 应用执行敏感路径和内容过滤。
4. 用户确认后调用已配置的 AI 服务。
5. 应用展示流式或分段结果，支持取消。
6. 用户可重新生成、编辑并保存最终摘要。

### 7.7 构建或运行项目

1. 用户选择已有任务或创建任务。
2. 应用展示命令、工作目录、参数和环境配置。
3. 用户确认后启动任务进程。
4. 任务中心实时接收输出并显示状态。
5. 用户可停止任务或等待任务完成。
6. 应用保存退出码、耗时、日志位置和结果。

### 7.8 备份与恢复

1. 用户选择项目和备份目标目录。
2. 应用检查项目状态、磁盘空间和排除规则。
3. 应用生成包含 `.git` 的 ZIP，并计算校验值。
4. 用户在备份中心选择 ZIP 和新的恢复目录。
5. 应用解压并校验文件结构和 Git 可用性。
6. 用户确认后将恢复项目导入项目列表。

## 9. 技术方案与系统边界

### 9.1 总体架构

建议采用以下分层：

- React 渲染层：页面、交互、状态展示和表单校验。
- Preload 桥接层：通过 contextBridge 暴露白名单 API，隔离渲染层与 Node.js 能力。
- Electron 主进程服务层：项目、账号、Git、任务、备份、分析和 AI 编排。
- Provider Adapter 层：GitHub、Gitee、GitLab API 适配。
- Git Service 层：Git CLI 调用、输出解析、凭据注入和风险检查。
- Process Service 层：构建/运行/打包子进程、进程树终止和日志流。
- Storage 层：SQLite（node:sqlite）、Windows Credential Manager 和本地文件系统。

### 9.2 Git 执行

- 使用系统 Git CLI，支持用户配置 Git 路径。
- 通过 Node.js 子进程接口以参数数组方式调用 Git，禁止通过 shell 拼接用户输入。
- 统一处理编码、退出码、标准输出和标准错误。
- 支持 HTTPS 和 SSH 两类远程地址。
- HTTPS 凭据通过安全凭据辅助机制注入，不将 Token 写入 URL、命令日志或数据库。
- 对高风险命令建立显式白名单和用户确认机制。

### 9.3 远程平台适配

定义统一 Provider 接口，至少包含：

- 当前用户和权限检查。
- 仓库列表、搜索、创建、修改和删除。
- 仓库元数据刷新。
- OAuth 授权启动和回调处理。
- Token 验证和权限范围读取。

平台差异必须在适配层消化。平台不支持的字段或操作应返回结构化能力状态，前端据此禁用或说明，而不是依赖平台错误文本猜测。

### 9.4 AI 服务

AI 能力采用 Provider 接口，首版至少兼容一种远程模型服务，并预留 OpenAI-compatible API。AI 服务调用不应和 Git 核心流程强耦合；AI 不可用时，项目管理、Git 操作、结构分析和任务执行仍必须正常工作。

### 9.5 本地数据目录

建议将应用数据分为：

- SQLite 数据库：项目、账号元数据、任务配置、操作记录索引。
- 凭据存储：Windows Credential Manager。
- 日志目录：脱敏的应用和操作日志。
- 缓存目录：可清理的远程数据和分析缓存。
- 导出目录：用户主动导出的诊断包或日志。

具体目录位置应遵循 Windows 用户应用数据规范，并支持在设置中查看，不建议首版允许随意修改数据库目录。

## 10. 安全与隐私要求

### 10.1 凭据安全

- GitHub、Gitee、GitLab Token、OAuth 刷新令牌和 AI API Key 使用 Windows Credential Manager。
- SQLite、普通配置文件、操作日志、崩溃信息和诊断包不得出现凭据明文。
- 用户界面只显示掩码后的凭据标识，不支持回显完整令牌。
- 删除账号或凭据时同时清理对应凭据引用，并明确提示正在删除的范围。
- 认证失败日志只能记录平台、账号标识和错误类别，不能记录请求头或完整响应中的敏感字段。

### 10.2 文件和命令安全

- 所有用户可控路径必须进行规范化、存在性检查和路径越界检查。
- 解压 ZIP 时防止 Zip Slip 路径穿越。
- 任务命令、环境变量和工作目录在执行前显示给用户。
- 远程仓库 URL、分支名、文件路径和提交信息不得造成命令注入。
- 默认禁止强制推送、硬重置和清理未跟踪文件等破坏性命令。

### 10.3 AI 隐私

- AI 请求必须由用户主动触发。
- 用户可查看、确认和调整发送内容范围。
- 默认过滤 `.env`、密钥、证书、凭据、令牌和私有配置文件。
- AI 生成结果不自动执行、不自动提交、不自动推送。
- 在隐私设置中说明服务提供方、请求地址、数据类型和用户可撤回的配置。

## 11. 非功能需求

### 11.1 兼容性

- 支持 Windows 10 22H2 x64 和 Windows 11 x64。
- 支持中文、空格、括号和常见特殊字符路径。
- 支持 Git 2.x 的主流稳定版本；具体最低版本在开发阶段确定并在启动检测中提示。
- 不要求管理员权限即可完成安装和常用操作；访问受保护目录时明确提示权限原因。

### 11.2 性能

- 启动后在常见机器上尽快呈现主窗口，不因远程仓库或项目扫描阻塞 UI。
- 本地项目分析和 Git 命令在后台执行，界面保持可交互。
- 大型项目扫描支持取消、进度或阶段状态提示。
- 远程列表采用分页、增量加载或按需刷新，避免一次性加载过多数据。
- 日志和分析缓存必须有大小限制。

### 11.3 稳定性

- Git、远程 API、AI、备份和任务执行彼此隔离，单个模块失败不应导致应用主进程退出。
- 任务、备份和移动操作支持取消或安全终止。
- 应用异常退出后，数据库保持可恢复，未完成任务标记为中断。
- 文件移动和恢复采用临时目录、校验和最终切换策略，避免半成品被当作成功结果。

### 11.4 可观测性

- 重要操作记录结构化事件和结果。
- 日志级别至少包含 error、warn、info、debug，生产默认不启用 debug。
- 错误提示同时给出用户可理解的原因和可执行的下一步。
- 支持导出脱敏诊断信息，便于问题反馈。

### 11.5 可访问性与交互

- 关键操作同时支持鼠标和键盘完成。
- 破坏性操作必须有明确名称、风险提示和二次确认。
- 长时间操作展示运行状态、进度或阶段信息，不能只显示无响应窗口。
- 空状态、加载状态、失败状态和无权限状态必须有明确界面。


## 12. 错误处理规则

统一错误类别：

| 类别 | 示例 | 处理要求 |
| --- | --- | --- |
| Validation | 路径非法、名称为空、命令缺失 | 阻止执行并定位具体输入 |
| Environment | Git 未安装、命令不存在、权限不足 | 展示环境问题和设置入口 |
| Authentication | Token 失效、OAuth 取消、权限不足 | 不重试敏感操作，提示重新授权 |
| Network | DNS、超时、限流、服务不可用 | 保留操作上下文，允许用户重试 |
| Git | 冲突、非快进、分支不存在 | 保留现场，展示分支和文件状态 |
| Filesystem | 目录不存在、磁盘空间不足、文件占用 | 不删除源文件，提示处理方式 |
| Process | 退出码非零、任务超时、进程无法终止 | 保存日志和退出状态 |
| AI | 配额、模型、内容过滤、响应解析失败 | 不影响其他项目功能，支持重试 |
| Internal | 数据库或应用内部错误 | 记录诊断信息，避免暴露敏感数据 |

错误提示不得只展示原始命令或堆栈。技术细节可通过“查看详情”展开，详情仍需脱敏。

## 13. 验收标准

### 13.1 功能验收

- 应用在 Windows 10 22H2 x64 和 Windows 11 x64 上可安装、启动和卸载。
- 首次启动可检测 Git，并允许用户配置 Git 路径。
- GitHub、Gitee、GitLab 至少各完成一次账号连接、仓库查询和克隆测试。
- OAuth 和 Personal Access Token 认证均有可验证的成功和失败路径。
- 应用重启后账号状态、项目元数据和任务配置仍然存在。
- 令牌和 AI API Key 不出现在 SQLite、界面、日志和诊断包中。
- 远程仓库可创建、修改、删除、刷新和克隆；删除操作有二次确认。
- 本地仓库可导入、初始化、登记、移动、移除记录和删除文件。
- Git 状态、提交、拉取、推送、获取、同步、分支切换和冲突提示可用。
- 有未提交修改时，高风险同步或删除操作能给出明确提示。
- 项目可以收藏、打标签、维护摘要和备注。
- 可以查看目录结构、语言统计、依赖文件和项目类型。
- 已配置 AI 时可生成摘要；未配置 AI 时其他项目功能不受影响。
- 可以查看提交、分支、标签、版本和两个版本之间的变更范围。
- 构建、运行、打包任务可配置、启动、实时输出、停止和重新执行。
- 项目可以备份为包含 `.git` 的 ZIP，并恢复到新目录后正常执行 Git 操作。
- 操作失败时能查看错误类别、原因和脱敏日志。

### 13.2 安全验收

- 数据库搜索不到 Token、OAuth 刷新令牌和 AI API Key 明文。
- 日志、异常弹窗、任务输出和诊断包经过敏感信息遮蔽。
- HTTPS 令牌认证不写入远程 URL。
- ZIP 恢复拒绝路径穿越条目。
- 用户未确认时不执行破坏性 Git 命令和项目删除。
- AI 请求发送前展示数据范围，并默认排除敏感文件。

### 13.3 可靠性验收

- 网络断开时远程操作失败，但应用主窗口和本地项目仍可使用。
- Git 冲突时应用不自动覆盖冲突文件。
- 移动项目校验失败时源目录仍然完整可用。
- 备份失败时不会生成可被误认为成功的备份记录。
- 应用在任务运行时关闭或崩溃后，重启可将未完成任务标记为中断。

## 15. 交付拆分建议

### 阶段 0：工程骨架与安全基础

- 初始化 Electron、React、TypeScript 和 SQLite 工程。
- 建立渲染层与主进程的类型化 IPC 约定。
- 完成数据库迁移、配置目录、日志和 Windows 凭据存储封装。
- 完成 Git CLI 探测和基础进程执行能力。

### 阶段 1：本地仓库核心

- 本地项目导入、初始化、克隆登记和项目列表。
- Git 状态、提交、分支、获取、拉取、推送和操作记录。
- 项目收藏、标签、摘要和基础设置。

### 阶段 2：远程平台

- Provider 接口和 GitHub、Gitee、GitLab 实现。
- OAuth 和 Personal Access Token 认证。
- 远程仓库查询、创建、修改、删除、刷新和克隆。

### 阶段 3：分析与迭代

- 目录树、语言统计、项目类型和依赖识别。
- 提交时间线、分支、标签、版本和差异查看。
- AI Provider、上下文预览、摘要生成和隐私过滤。

### 阶段 4：任务与备份

- 构建、运行、打包任务。
- 实时日志、任务停止、进程树管理。
- ZIP 备份、恢复、校验和导入。

### 阶段 5：发布质量

- Windows 安装包、升级和卸载验证。
- 安全测试、兼容性测试、性能测试和端到端回归。
- 诊断包、文档、示例配置和发布说明。

## 16. 待确认和实施前决策

以下问题不阻塞需求基线，但在对应模块开发前需要确定：

1. 产品名称、应用图标和品牌视觉规范。
2. OAuth 回调采用本地回环地址还是自定义 URI Scheme。
3. 首版默认支持的 AI 服务商和模型，是否同时提供 OpenAI-compatible 配置。
4. 默认是否允许访问代理设置，还是完全继承系统代理。
5. Git 最低支持版本和是否内置 Git 分发包。
6. 是否支持 Windows ARM64；当前范围暂定仅 x64。
7. ZIP 压缩级别、备份保留数量和大项目备份的空间提示阈值。
8. 是否在首版提供应用自动更新，以及更新源和签名策略。
9. 远程删除、批量操作和任务执行是否需要额外的管理员确认策略。
10. AI 数据是否允许通过第三方服务处理，及产品隐私政策和用户授权文案。

## 17. 需求变更规则

- 新增功能必须说明用户价值、影响模块、优先级和验收标准。
- 涉及凭据、文件删除、Git 历史修改或 AI 数据发送的变更必须经过安全评审。
- 变更后同步更新需求编号、数据模型、流程、测试策略和验收标准。
- P0 功能未达到验收标准前，不以 P1/P2 功能替代首版质量目标。
